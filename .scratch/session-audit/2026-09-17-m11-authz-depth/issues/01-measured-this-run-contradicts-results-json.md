# CURRENT_STATE "Measured this run" latencies contradict the committed results.json

Status: resolved (2026-09-17)
Source: session-audit 12ed44b..a951ad1 (pattern still live at 89ec9db)

Resolution: took the "drop the digits" branch — the four advisory latency
numbers are removed from CURRENT_STATE's "Measured this run" (they are
regenerated by every `npm test` via `tests/slo.test.ts`, so any copy is stale
by construction); the section now cites only stable facts (denominators,
rates, slo.pass) and points at `benchmarks/results.json` for latencies.
Verified post-fix: 2122/2122, 0/101, 14 targets, exit 0.

## What's wrong

`CURRENT_STATE.md` writes "Measured this run (`benchmarks/results.json`)" and then
cites latency numbers that are not in the committed artifact of the same tree.

- At `2911d39`/`a951ad1` (M11): docs cite 0.250 / 0.271 / 0.109 / 0.006 ms, but
  `git show a951ad1:benchmarks/results.json` has 0.289 / 0.240 / 0.106 —
  `CURRENT_STATE.md:186-188` vs `benchmarks/results.json:evidence.*Latency*`.
- At the merged tip `89ec9db` (M13 repeated the mistake): docs say 0.228 / 0.259 /
  0.102 (`CURRENT_STATE.md:211-212`) while `git show 89ec9db:benchmarks/results.json`
  says 0.337 / 0.300 / 0.101.

The M11 demo/docs commit wrote its numbers from an earlier benchmark invocation,
then a later invocation regenerated the artifact — the two were never the same run.

Root cause confirmed at M13 (audit `.scratch/session-audit/2026-09-17-m13-runtime-realism/`):
`npm test` itself regenerates the artifact — `tests/slo.test.ts` shells out to
`node src/cli.ts benchmark` — so any latency digits copied in before the final
gate run are already stale at commit time.

## Why it matters

AGENTS.md: "Docs that drift from code rot into lies. Fix them in the same
commit." The line explicitly claims provenance ("Measured this run
(benchmarks/results.json)") — an auditor diffing the doc against the artifact
finds a mismatch, which is exactly the credibility damage ADR-014's honesty rule
exists to prevent. It is now a recurring pattern across two milestones.

## Minimal fix

Regenerate `benchmarks/results.json` LAST, then copy its exact field values into
the "Measured this run" section in the same commit — or drop the specific
latency digits and cite only the stable facts (`slo.pass = true`,
`auditCompleteness 2122/2122`, denominators). One or the other; never both ways
across milestones.
