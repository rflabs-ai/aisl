## 1. Fix — remove the redundant synthetic-resource registration in `evaluate()`

**Where:** `src/pdp.ts:362-373` (the `if (!this.registry.get(resourceId) && resourceId.startsWith('audit-log:'))` block at the top of `evaluate()`).

**Why:** `AuthorizationService.queryAudit()` already registers
`audit-log:<principal.tenantId>` before delegating to `authorize()`
(`src/pdp.ts:336-346`). The `evaluate()` block is dead code on the supported
path and live only for direct `authorize()` calls with a caller-constructed
`audit-log:*` id — which the M6 spec §7 says must be rejected ("derive
`resourceId = 'audit-log:' + principal.tenantId` ... no caller-controlled
route"). With the block removed, a direct `authorize()` call on an
`audit-log:*` id denies `unknown-resource` (fail closed) instead of
materializing a synthetic resource.

**Change:** delete the block. Do not touch the tenant check, the candidate
filter, or `queryAudit()`'s registration.

**Test (add to `tests/m6-audit-query.test.ts`):**

```ts
test('direct authorize() on a caller-constructed audit-log id is denied (unknown-resource)', () => {
  const { world } = setupAuditTestWorld();
  issueAuditCap(world, world.user.id, ['query.audit']);
  const decision = world.authorization.authorize({
    principal: world.user,
    action: 'query.audit',
    resourceId: `audit-log:${TENANT_A}`,   // same value queryAudit would derive — still denied
  });
  assert.equal(decision.decision, 'deny');
  assert.equal(decision.denyReason, 'unknown-resource');
});
```

Existing `service.query()` / `service.exportFor()` tests must stay green —
they route through `queryAudit()`, which still registers.

## 2. Fix — `AuditExport.generatedAt` must come from the service clock

**Where:** `src/audit-query.ts:138` — the success path returns
`this.eventLog.exportFor(filters)` raw, and `EventLog.exportFor()` sets
`generatedAt = Date.now()` (`src/events.ts:379`). The deny path
(`src/audit-query.ts:130`) already uses `this.clock()`. Pinned-clock tests
currently see wall time on the success path.

**Change (one line, keep it lazy):**

```ts
const exported = this.eventLog.exportFor(filters);
return { ...exported, generatedAt: this.clock() };
```

Do **not** change `EventLog.exportFor`'s signature — `EventLog` has no clock
by design (`append()` also uses `Date.now()` for event timestamps; see the
ponytail comment at `src/events.ts:272`). The service owns the injectable
clock.

**Test:** pin `world.clock.set(<t>)`, issue the capability, call
`service.exportFor(...)`, assert `exported.generatedAt === t`. (The existing
"Export shape" test asserts `typeof generatedAt === 'number'` — tighten or
add a case.)

## 4. Fix — single-bound time filters can still dump full history

**Where:** `src/audit-query.ts:73-105` (`validateFilters`). The 90-day check
only fires when **both** `fromTime` and `toTime` are present. Today
`{ fromTime: 0 }` (no upper bound) and `{ toTime: now }` (no lower bound) both
return full history — exactly what the M6 spec §7 says the 90-day rule
defends against.

**Change — replace the time-range block with three cases:**

```ts
const at = this.clock();
if (filters.fromTime !== undefined && filters.toTime !== undefined) {
  if (filters.fromTime > filters.toTime) {
    throw new AuditFilterError(`fromTime (${filters.fromTime}) cannot be after toTime (${filters.toTime})`);
  }
  const rangeMs = filters.toTime - filters.fromTime;
  if (rangeMs > MAX_TIME_RANGE_MS) {
    throw new AuditFilterError(`time range exceeds 90 days (${rangeMs} ms > ${MAX_TIME_RANGE_MS} ms)`);
  }
} else if (filters.fromTime !== undefined) {
  // Open-ended "since T" query: the effective upper bound is now.
  const rangeMs = at - filters.fromTime;
  if (rangeMs > MAX_TIME_RANGE_MS) {
    throw new AuditFilterError(`time range exceeds 90 days (from ${filters.fromTime} to now)`);
  }
} else if (filters.toTime !== undefined) {
  // Unbounded lower edge: cannot be limited to 90 days.
  throw new AuditFilterError('toTime requires fromTime: an unbounded lower edge cannot be limited to 90 days');
}
```

**Check for callers first (AGENTS.md: grep every caller):** `tests/`,
`src/cli.ts` demo section 13, and the benchmark use both-bounds or no bounds —
verify with grep for `toTime` before landing. None should pass `toTime`-only.

**Tests (extend the bad-filter test or add cases):**

- `{ fromTime: clock - 91d }` throws `AuditFilterError`.
- `{ fromTime: clock - 1d }` does not throw (and returns).
- `{ toTime: clock }` alone throws `AuditFilterError`.
- Existing both-bounds cases unchanged (in-range passes; 91-day span throws;
  `fromTime > toTime` throws).

**Note:** this is a deliberate tightening beyond the M6 spec's literal text
(the spec never describes single-bound behavior). Say so in the Claim 21
mechanism sentence (part of §5).

## 6. Tests — prove the documented #6/#10 semantics

These behaviors are documented (Claim 21 + comments/JSDoc) but currently
unproven. Add to `tests/m6-audit-query.test.ts`:

**(a) export is authorized by a capability holding only `query.audit`:**

```ts
test('audit.export is implied by query.audit in capability scope (Claim 21)', () => {
  const { world, service } = setupAuditTestWorld();
  issueAuditCap(world, world.user.id, ['query.audit']);   // no audit.export listed
  const exported = service.exportFor(world.user, { tenantId: TENANT_A, fromSeq: 0, toSeq: 999 });
  assert.ok(exported.events.length > 0);
  const last = world.eventLog.all().at(-1)!;
  assert.equal(last.action, 'audit.export');
  assert.equal(last.decision, 'allow');
});
```

**(b) the reverse does not hold — `audit.export` alone cannot query:**

```ts
test('a capability holding only audit.export cannot query (Claim 21, reverse direction)', () => {
  const { world, service } = setupAuditTestWorld();
  issueAuditCap(world, world.user.id, ['audit.export']);
  const result = service.query(world.user, { tenantId: TENANT_A });
  assert.equal(result.decision.decision, 'deny');
  assert.equal(result.decision.denyReason, 'no-capability');
  assert.equal(result.length, 0);
});
```

**(c) export bounds are result bounds:**

```ts
test('export bounds reflect returned events, not requested filters (Claim 21)', () => {
  const { world, service } = setupAuditTestWorld();
  issueAuditCap(world, world.user.id, ['query.audit']);
  const exported = service.exportFor(world.user, { tenantId: TENANT_A, fromSeq: 0, toSeq: 999_999 });
  const all = world.eventLog.all();
  assert.equal(exported.fromSeq, 0);
  assert.ok(exported.toSeq < 999_999);
  // The export's own audit.export decision event is appended before the read,
  // so it is the last returned event.
  assert.equal(exported.toSeq, all.at(-1)!.seq);
  assert.equal(exported.head, all.at(-1)!.eventHash);
});
```
